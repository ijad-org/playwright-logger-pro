# Changelog

## [0.3.0] - 2026-10-30

### Added

- **Coloured curl output.** The curl printed to the console is coloured: `curl` bold, a colour each for the method, the URL, query parameter and header names, JSON keys and strings (when the body is valid JSON) and `#` comments, and `***` in bold + inverse video. Flags, `\` continuations, quotes and punctuation keep the default foreground. No white, yellow, cyan or dim text. Removing the ANSI codes always gives exactly the plain command, and with colours off the output is byte-identical to before.
- **Palette that reads on black and white terminals.** Every colour is chosen from the default xterm palettes so that its WCAG contrast is at least 4.5:1 on both `#000000` and `#ffffff` in the 256-colour palette (`38;5;N`: 63, 29, 98, 131, 163, 243) and at least 3:1 in the 16-colour fallback (blue 12, magenta 5 and 13, red 1 and 9, grey 8; the 16 colours have no green that reaches 3:1 on white, so POST and strings are not green there). The 256-colour palette is used when `COLORTERM` is `truecolor`/`24bit`, `TERM` contains `256color` or the terminal reports at least 8 bits, otherwise the 16 basic colours. `buildCurl()` takes an optional `colorDepth` (`8` or `4`) to choose. `npm run contrast` prints the ratios of every element on both backgrounds and a unit test enforces the limits.
- **Coloured curl by default in a local terminal.** A plain `npx playwright test` whose runner stdout is a terminal now colours the curl in worker output with no `PLAYWRIGHT_FORCE_TTY` or `curlFormat.colors: true`. The runner process (where the spec files import this package; checked on Playwright 1.30, 1.39, 1.48 and the latest) sets `PLP_RUNNER_TTY=<runner pid>:<colour depth>` when its own stdout is a real terminal and it is not on CI, `NO_COLOR` is unset, `FORCE_COLOR`/`DEBUG_COLORS` are not `0`/`false` and `TERM` is not `dumb`; workers inherit it and trust it only when the pid is their parent's, so a copy inherited by a nested run or set by hand is ignored. Every other gate still applies (CI, `NO_COLOR`, `TERM=dumb`, resolved `colors`, custom sink, piped output stays plain, also on Playwright 1.30-1.39 whose workers fake a terminal); `curlFormat.colors: true` still overrides. `package.json` `sideEffects` now lists the two entry points, since importing them runs this check.
- **Colour gating.** With `curlFormat.colors: 'auto'` the curl is coloured only when `NO_COLOR` is unset (it always wins), the process is not on CI (`CI` and the common CI service variables), the output is a terminal (`process.stdout.isTTY`, the runner's own stdout being one, or `PLAYWRIGHT_FORCE_TTY` set to anything but `0`/`false`), the resolved `colors` is true and the sink is the console. `FORCE_COLOR` (which `playwright test` sets for its workers, whose stdout is piped) and a top-level `colors: true` alone no longer colour the curl in CI or non-TTY output; piped workers stay plain unless `PLAYWRIGHT_FORCE_TTY` or `curlFormat.colors: true` is set. An explicit `curlFormat.colors: true` is an override that bypasses these checks.
- **`curlFormat` option** (`ApiLoggerConfig`): `colors` (`true`, `false` or `'auto'`, the default), `multiline` (default `true`; `false` prints a single line with `#` notes on their own preceding lines) and `file`. Invalid values warn once and use the default. New exported types `CurlFormatConfig` and `ResolvedCurlFormat`.
- **`curl.sh` per test** (with the `test` fixture): the plain, redacted curl commands of a test are written to `curl.sh` in the test's output directory and attached to the report. The header is `#!/bin/sh`, `# <spec file relative to rootDir/testDir>:<line>` (control characters and escape sequences removed) and a generic comment; **the test title is not written** (it can carry secrets or terminal escape sequences). One line goes through the sink: `curl.sh: attached to the test report (see "curl.sh" in the HTML report; also saved in this test's output folder)`; it names no path, because Playwright's output folder is derived from the title. `curlFormat: { file: false }` turns it off. Redaction is the same as for the printed curl; there is no unredacted mode.
- `buildCurl()` accepts `colors`, `colorDepth` and `multiline` in its options (all optional; the signature is backward compatible).

### Changed

- With a custom `sink` and no explicit `colors`, colours now default to **off** for all apiLog lines, so ANSI codes do not reach a file sink. An explicit `colors: true` keeps them. Before, a custom sink received colours whenever the environment enabled them.
- `curlFormat.colors: 'auto'` follows the resolved `colors` only on the default console sink; with a custom `sink` the curl is plain unless `curlFormat.colors` is `true`.
- Docs: Playwright's HTML report step titles show the full request URLs of `request` calls (the logger cannot mask them), and `redactBodyKeys` is empty by default and masks JSON/form keys only (XML and raw text bodies are not scrubbed). Behaviour unchanged.

## [0.2.0] - 2026-10-30

### Added

- **Browser action logging (`browserLog`).** A per-test timeline of what the test did in the browser: actions on page, frame, locator, keyboard, mouse, touchscreen, context and browser, navigations, console messages, page errors, popups, downloads, dialogs, optional network, `test.step` boundaries, and a duration for every action. See the README section *Browser action logging*.
- **`playwright-logger-pro/fixtures` now provides both loggers.** New `browserLog` option fixture, `browserLogger` fixture (`note()`, `events()`, `render()`), `LoggerOptions` type for `defineConfig<LoggerOptions>()`, and a `mergeTests` that keeps the step integration (Playwright 1.39+).
- `attachBrowserLogger(pageOrContext, config?)` for pages you manage yourself (scripts, global setup, a page shared from `beforeAll`).
- Secret masking by default: `fill()`/`type()` into password-like targets, keyboard input after such a target, literal `redact.values`, sensitive object keys inside arguments, header/cookie/credential values, URL userinfo passwords, console text and page errors. Opt-in `redact.inspectInputType` DOM probe. One shared sensitive-key list (`DEFAULT_SENSITIVE_KEYS`) for both loggers.
- Outputs: live `print`, an `'on-failure'` block, a `browser-log` report attachment (text or JSONL), and per-test files (`file`, `fileFormat`, `fileDir`). ANSI never reaches files or attachments.
- apiLog lines are copied into the browser log's attachment and files (`includeApiLog`), never printed twice.
- Documentation site (Docusaurus, GitHub Pages) with guides, configuration reference, API docs, migration notes and offline search; the changelog page is generated from this file.
- CI matrix (Playwright 1.30 / 1.39 / 1.48 / latest, Chromium; latest also Firefox and WebKit), a weekly prototype-drift job, a package check (`publint`, `attw`, CJS and ESM smoke tests) and an overhead benchmark.

### Changed

- **`browserLog` is enabled by default, with quiet defaults**: nothing is printed or attached while a test passes; on failure the timeline is printed once and attached to the report. Opt out per project or suite with `browserLog: { enabled: false }`. When disabled, no page-level patch or listener is installed for that test.
- **Step locations stay in your spec file.** Wrapper frames of this library are hidden from Playwright's stack attribution, which also fixes `request.*` steps and errors of the existing apiLog fixture (they used to point into `dist/`).
- On Playwright 1.30–1.48 the step title of a logged request is `apiRequestContext.get(...)` again (it was `apiRequestContext.apply(...)`).
- `package.json` `exports` now has per-condition types (`.d.mts` for `import`, `.d.ts` for `require`) and exposes `./package.json`; the build targets Node 16 syntax and ships shims for `__dirname`/`import.meta.url`.
- `redactHeaders()` accepts an optional third argument (the mask, default `***`).

### Fixed (QA findings on this release)

- **PCL-30 (critical): typed secrets are learned.** A value typed into a field that is masked in its action line (`fill`, `type`, `pressSequentially`, `keyboard.type`, `insertText`, prompt answers) is now masked everywhere the logger outputs, for the rest of the test: console messages, page errors, network and navigation URLs (query strings included, also percent-encoded), dialog text, notes, attachment, files, JSONL and sink events. Values shorter than 4 characters are not learned.
- **PCL-31: card fields.** `#card`, `[name=cardnumber]`, `[autocomplete=cc-number]`, `getByLabel('Card')`, `getByLabel('Credit card')`, `#cvc`, `#securityCode`, `#totp` … are detected from the selector. `inspectInputType` stays off by default.
- **PCL-32: Authorization tokens.** `Bearer X` / `Basic …` / `Token X` set through `setExtraHTTPHeaders` (or the `extraHTTPHeaders` option) also masks the bare token `X`, the decoded Basic password and the values of a `Cookie` header.
- **PCL-33 (docs): Playwright-owned artifacts.** The README now says that HTML report step titles, `error-context.md` and traces can contain raw values even with traces off, and that `redact.*` does not affect them.
- **PCL-34: malformed `test.step` location.** Stack frames without parentheses (`at /abs/file.ts:11:5`) no longer keep the `at ` prefix; `file://` URLs and Windows paths are handled.
- **PCL-35: `location: true`** reports the spec file and line instead of this library's `dist/` file (library, Playwright and node frames are skipped).
- **PCL-27 / PCL-28: redirect replay.** In a chain of redirects each step's `curl` starts from the previous step's request, so a body dropped by a 301/302/303 no longer comes back on a later 307/308. Headers follow the redirect rules of the installed Playwright (Cookie and cross-origin Authorization handling differ between 1.30–1.31, 1.32–1.59 and 1.60+).
- **PCL-47: query strings in browserLog URLs.** Values of sensitive query parameters (apiLog's `redactQueryParams` defaults: `api_key`, `apikey`, `token`, `access_token`, `password`, `secret`) are masked by default in every URL browserLog prints: action arguments, navigations and redirect targets, popups, downloads, network lines and URLs in console text and errors. It shares apiLog's `redactUrl` logic and list; new `redact.queryParams` adds names. `redact.values` still applies on top.
- **PCL-46: `redact.selectors` and `redact.keys` add to the defaults** instead of replacing them, as apiLog's lists do (`#nick` no longer un-masks `#password`/`#pin`). `replaceDefaultRedaction: true` in the `apiLog` option opts out. **Behaviour change:** configs that relied on replacing the defaults (to stop masking `#pin`, say) must now set it.
- **PCL-36: option validation.** `browserLog` warns once on unknown options and on invalid types or values and falls back to the defaults; `maxEvents` of `0`, negative or fractional values no longer suppress the failure block.
- **PCL-37: `inspectInputType` status.** A fill that completed is reported as completed (value still masked) when the test ends before the probe answers, not as "still pending".
- **PCL-38: chronological timeline.** Actions are ordered by their start, followed by the events that happened while they ran, in the stored events, the failure block and live output. A page's "opened" line carries the time the page appeared.
- **PCL-39 (critical): more spellings of a learned secret are masked.** On top of the literal value and the percent-encoded and plain `JSON.stringify` forms, each learned secret (typed values, `addCookies`, `setExtraHTTPHeaders`, `setHTTPCredentials`) is now also masked as JSON with escaped slashes (`\/`), as `\uXXXX` JSON (PHP `json_encode` defaults, Python `ensure_ascii`, every character escaped; lower and upper case hex, surrogate pairs as two escapes) and as legacy `escape()` (`%XX` / `%uXXXX`, both hex cases). The variants are computed once when a secret is learned and deduplicated. The README lists exactly these forms.
- **PCL-40 (docs): masking is literal-form based.** Base64, double encoding, HTML entities, values split across `console.log` arguments and fragments typed with `keyboard.type()` mid-field are not detected; the README limits section says so and what to do instead (`redact.values`, turning off the console and network channels, not logging such values). Turning off `browserConsole` and `network` does not cover action lines, page errors, dialog text or navigation URLs; for those, add the encoded form to `redact.values`, or use `actions: false`, `pageErrors: false` or `navigation: false` (`navigation` covers both dialog text and navigation URLs).
- **PCL-41: expiry and PAN fields.** `autocomplete` `cc-exp`, `cc-exp-month`, `cc-exp-year`, `cc-csc`, and names, ids, labels or placeholders such as "Expiry date", "Expiration", "Exp date", "card expiry", "PAN" and "card number" are treated as sensitive. Whole words only, so `company`, `panel` or `expires in` stay clear.
- **PCL-42 (docs): server-set cookies.** Cookies set by a `Set-Cookie` response header are not learned or masked; documented in the limits section.
- **PCL-43: Playwright 1.64 types.** `httpCredentials` may be an array (one entry per origin); every password in it is collected. `mergeTests` is typed so that `src/fixtures.ts` also compiles against the 1.30 types. Typecheck and build verified against the lowest supported and the latest `@playwright/test` types.
- **PCL-44: expiry and PAN detection reads camelCase.** Selector, name, id, placeholder and label text is split on camelCase boundaries and on `_`, `-` and space before matching, so `#cardExpDate`, `#panNumber` and `[name=cardPAN]` are detected, as are the placeholders `MM/YY` and `MM/YYYY` and the labels "Valid thru" and "Valid through". The same splitting applies to user-supplied `redact.selectors`. `company`, `panel`, `span`, `express`, `expand`, `pantry`, `Japan`, `Expense` and "expires in" stay clear.
- **PCL-44 (docs):** the limits section now says that turning off `browserConsole` and `network` does not cover action lines, page errors, dialog text and navigation URLs (use `redact.values`, `actions: false`, `pageErrors: false` or `navigation: false`), that a value mixing escaped and literal forms or upper- and lower-case hex is not matched (case is per value), and how to pass an array to `test.use({ httpCredentials })`.

### Known limitations

- Secret masking is literal-form based: base64, double encoding, HTML entities, values split across `console.log` arguments, and fragments typed with `keyboard.type()` mid-field are not detected, and cookies set by the server with `Set-Cookie` are not masked. Use `redact.values`, turn off the console and network channels, or avoid logging such values. Turning off `browserConsole` and `network` does not cover action lines, page errors, dialog text or navigation URLs; for those, add the encoded form to `redact.values`, or use `actions: false`, `pageErrors: false` or `navigation: false` (`navigation` covers both dialog text and navigation URLs).
- Playwright's own artifacts record raw action parameters and page state, **even with traces off**: HTML report step titles (newer versions: `Fill "<value>"`), the `error-context.md` snapshot, traces, screenshots and videos. This logger only redacts its own outputs; `redact.*` does not affect Playwright's. See the README for what helps.
- `test.step` integration needs Playwright 1.48+ (older versions cannot keep the step location); actions are still logged there, without step markers.
- A password field whose selector, label and placeholder do not look like one is only detected with `redact.inspectInputType: true`, `redact.values`, a custom `redact.selectors` entry, or `redact.fillValues: 'always'`.
