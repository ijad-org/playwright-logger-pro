# Configuration

Two option fixtures configure the loggers. Both are optional and flat objects.

```ts title="playwright.config.ts"
import { defineConfig } from '@playwright/test';
import type { LoggerOptions } from 'playwright-logger-pro/fixtures';

export default defineConfig<LoggerOptions>({
  use: {
    apiLog: { curl: 'on-failure' },
    browserLog: { network: 'failed', redact: { values: [process.env.E2E_PASSWORD].filter((v): v is string => !!v) } },
  },
});
```

:::info Documentation is checked against the code
The option tables on this page are compared with the library's option types and exported defaults when the site is built (`npm run check-config` in `website/`). A missing or extra option, or a wrong default, fails the build.
:::

## Precedence and merge rules {#precedence}

- **`test.use()` replaces the whole object.** `test.use({ apiLog: { curl: true } })` replaces the `apiLog` from your config; it does not merge. Repeat the options you still want. The same holds for `browserLog`.
- **`redact` is merged one level deep** with the defaults: setting `redact: { values: [...] }` keeps the default `selectors`, `keys` and the rest. Setting `redact.selectors` or `redact.keys` **adds** to the defaults; `apiLog.replaceDefaultRedaction: true` replaces them.
- **`undefined` means the default.** An option explicitly set to `undefined` uses its default, which lets you write `colors: process.env.CI ? true : undefined`.
- **Explicit `colors` wins** over every colour environment variable.
- **Invalid values never throw.** An unknown option or invalid value prints a one-time `[playwright-logger-pro]` warning naming the option, and the default is used. (`maxEvents` must be a positive integer so a bad value can never switch the failure block off.)
- **`httpCredentials` arrays.** Playwright reads `test.use({ httpCredentials: [a, b] })` as `[value, options]`, not as two credentials. To pass an array, write `test.use({ httpCredentials: [[a, b], { scope: 'test' }] })`.
- **Redaction lists are merged** with the built-in lists, in apiLog and in browserLog's `redact`; see [`replaceDefaultRedaction`](#apilog-options), the one switch that drops the defaults of both.

## apiLog options {#apilog-options}

Configures request logging for the `request` fixture and `wrapRequestContext()`.

{/* config-table: apiLog */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | `false` makes the wrapper a transparent pass-through. |
| `colors` | `boolean` | auto | `true`/`false` force ANSI colours on/off (`true` wins over `NO_COLOR`). Auto: see [Environment variables](#environment-variables). With a custom `sink` and no explicit `colors`, auto means **off**, so ANSI codes do not reach a file. |
| `format` | `'compact' \| 'verbose'` | `'compact'` | `'compact'`: one line per call and detail only where something went wrong, printed by the [reporter](./compact-output.mdx). `'verbose'`: the 0.3 output (request, headers, bodies, response, curl) printed live. |
| `curl` | `boolean \| 'on-failure' \| '5xx' \| '4xx+' \| 'always' \| 'never'` | `'5xx'` | Which calls get a curl (and a `curl.sh` attachment): `'5xx'` status >= 500 and network errors, `'4xx+'` status >= 400 and network errors, `'always'`, `'never'`. Legacy: `true` is `'always'`, `false` is `'never'`, `'on-failure'` is any non-2xx. With `format: 'verbose'` the default is `false`, as in 0.3. Other values warn and use the default. |
| `slowThresholdMs` | `number` | `1000` | A call at least this slow gets `▲` and a yellow time, and counts in the footer. |
| `timeColumn` | `number \| 'auto'` | `82` | Column where the timing ends. `'auto'` fits the terminal width. A longer line keeps a 2-space gap and, past the terminal width, loses the middle of its query string. |
| `details` | `'failed-tests' \| 'always' \| 'never'` | `'failed-tests'` | When a request with status >= 400 or a network error gets its `│` block: only when its test failed, always, or never. |
| `bodyPreviewChars` | `number` | `200` | Length of the response body preview in the block, in characters. |
| `theme` | `'ansi' \| 'dark' \| 'light'` | `'ansi'` | `'ansi'` uses the 16 basic colours of your terminal theme. `'dark'` and `'light'` are true-colour palettes (the ones of the README screenshots). |
| `ascii` | `boolean` | `false` (`true` on legacy Windows consoles) | ASCII symbols (`\|` `<-` `^` `->` `ok` `x`) instead of Unicode. |
| `mask` | `{ headers?, query?, bodyKeys? }` | `{}` | **Extra** names to mask, merged with the built-in lists and with `redactHeaders`, `redactQueryParams` and `redactBodyKeys`. The mask is always `***`. |
| `curlFormat` | `{ colors?, multiline?, file? }` | `{ colors: 'auto', multiline: true, file: true }` | How the curl is printed and saved: colours, single-line output and the `curl.sh` file. See [`curlFormat`](#curlformat). |
| `logHeaders` | `boolean` | `true` | Log request and response headers (compact: keep them in the JSON attachment). |
| `logBody` | `boolean` | `true` | Log request and response bodies (compact: keep them in the JSON attachment and show the response preview). |
| `maxBodyLength` | `number` | `2000` | Truncate logged bodies beyond this many characters. A number ≥ 0; `Infinity` disables truncation. Applies to `format: 'verbose'` and the JSON attachment; the compact curl is cut at 2 KB. |
| `redactHeaders` | `string[]` | `[]` plus the built-in `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `x-auth-token` | **Extra** header names masked in logs and curl. Case-insensitive; merged with the defaults. |
| `redactQueryParams` | `string[]` | `[]` plus the built-in `api_key`, `apikey`, `token`, `access_token`, `refresh_token`, `key`, `password`, `secret`, `signature`, `sig` | **Extra** query parameter names masked in logged URLs and curl. Merged with the defaults. |
| `redactBodyKeys` | `string[]` | `[]` plus the built-in `password`, `token`, `accessToken`, `refreshToken`, `secret`, `apiKey`, `cardToken`, `cardNumber`, `cvv`, `pin`, `access_token`, `refresh_token`, `api_key`, `card_number` | **Extra** JSON/form body keys and multipart field names masked in logged bodies and curl, at any depth. |
| `replaceDefaultRedaction` | `boolean` | `false` | `true` drops the built-in lists: only your lists are used, and a list you leave out redacts nothing. Also applies to `browserLog.redact` (`selectors`, `keys`, `queryParams`, `headers`). Dangerous. |
| `sink` | `(line: string) => void` | `console.log` | Where log lines go. A throwing sink warns once and falls back to `console.log`. |
| `baseURL` | `string` | fixture: `use.baseURL` | Used to show absolute URLs and the original URL of redirected requests. The fixture fills it in; pass it yourself with `wrapRequestContext()`. |
| `extraHTTPHeaders` | `Record<string, string>` | fixture: `use.extraHTTPHeaders` | Headers the context sends with every request, shown in logged headers and curl. The fixture fills it in; with `wrapRequestContext()` pass the headers you gave `newContext()`. |

### `curlFormat` {#curlformat}

Presentation of the curl command. Only the printed command changes; the redaction is the same everywhere. An invalid value warns once and uses the default.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `colors` | `boolean \| 'auto'` | `'auto'` | Colours the curl and, with `format: 'compact'`, the whole output printed by the fixture (without the reporter). `'auto'` colours only when `NO_COLOR` is unset, the process is not on CI, the output is a terminal (stdout is a TTY, the test runner's own stdout is one, or `PLAYWRIGHT_FORCE_TTY` is set), the resolved `colors` is true and the sink is the default console one. A local `npx playwright test` in a terminal therefore colours it with no setting. `FORCE_COLOR` and a top-level `colors: true` alone do not colour it in CI or when piped. `true` is an **explicit override** that skips all of these checks (ANSI codes may reach CI logs, files and custom sinks); `false` never colours. See [When the curl is coloured](./api-logging.mdx#curl-colours-gate). |
| `multiline` | `boolean` | `true` | `false` prints the command on a single line, options joined by single spaces. Notes and redirect step comments stay on their own `#` lines above it. |
| `file` | `boolean` | `true` | With the `test` fixture, attach the curls to the report as scripts. Compact: `curl.sh` (or `curl-{n}-{METHOD}-{lastPathSegment}.sh`), `#!/usr/bin/env bash`, `${VAR}` placeholders for masked values. Verbose: one `curl.sh` (`#!/bin/sh`) and a one-line notice. Only applies while `curl` is enabled. |

See [API logging › curl output](./api-logging.mdx#curl-colours) for the colours, the colouring rules and the `curl.sh` file.

## Reporter options {#reporter-options}

`playwright-logger-pro/reporter` takes the display options of `apiLog` (they win over what the fixture recorded) and one more. See [Compact output](./compact-output.mdx).

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `slowThresholdMs`, `timeColumn`, `details`, `bodyPreviewChars`, `theme`, `ascii` | | as in [`apiLog`](#apilog-options) | Same meaning and defaults. |
| `curl` | `'5xx' \| '4xx+' \| 'always' \| 'never'` | from `apiLog.curl` | Which calls show their curl. The fixture decides which calls carry one (`apiLog.curl`, and every failed call); this can only show fewer, or more of the failed ones. |
| `colors` | `boolean \| 'auto'` | `'auto'` | `'auto'`: no colours on CI, with `NO_COLOR`, `FORCE_COLOR=0`, `TERM=dumb` or when stdout is not a terminal. `true` forces them on. |

### browserLog.redact {#browserlogredact}

{/* config-table: browserLog.redact */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `mask` | `string` | `'***'` | Replacement for masked values. |
| `fillValues` | `'auto' \| 'always' \| 'never'` | `'auto'` | Masking of typed values. `'auto'`: when the target looks sensitive. `'always'`: every typed value. `'never'`: none (`values` still applies). |

| `values` | `string[]` | `[]` | Literal secrets masked everywhere, in addition to the ones collected automatically. Values shorter than 4 characters are ignored. |

| `queryParams` | `string[]` | apiLog's resolved list: `api_key`, `apikey`, `token`, `access_token`, `refresh_token`, `key`, `password`, `secret`, `signature`, `sig` plus your `apiLog.redactQueryParams` | Extra query parameter names, added to apiLog's `redactQueryParams` (defaults included). Their values are masked in every URL the browser log prints. |
| `headers` | `string[]` | apiLog's resolved list: `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `x-auth-token` plus your `apiLog.redactHeaders` | Extra header names, added to apiLog's `redactHeaders` (defaults included). |
| `inspectInputType` | `boolean` | `false` | Opt-in DOM probe for `type=password` after a fill. One extra round trip per distinct field. |

## `buildCurl` options {#curl-options}

`buildCurl(info, redactHeaderNames?, options?)` is exported for building a curl yourself: `info` is a `RequestInfo`, the second argument lists header names to mask, and the third is `CurlOptions`:

{/* config-table: curl-options */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `redactQueryParams` | `readonly string[]` | none | Query parameter names whose values are masked in the URL. |
| `redactBodyKeys` | `readonly string[]` | none | JSON/form body keys and multipart field names whose values are masked. |
| `maxBodyLength` | `number` | none | Truncate the request body (and each form/field value) beyond this many characters. |
| `colors` | `boolean` | `false` | Colour the command with ANSI codes. Removing the codes gives exactly the uncoloured command. |
| `colorDepth` | `4 \| 8` | detected | Palette used with `colors`: `8` for the 256-colour palette (`38;5;N`), `4` for the 16 basic colours. Detected from `COLORTERM`, `TERM` and the terminal when omitted. See [API logging › Colours](./api-logging.mdx#curl-colours). |
| `multiline` | `boolean` | `true` | One option per line with `\` continuations; `false` gives a single line. |
| `mask` | `string \| (key: string) => string` | `'***'` | What replaces a masked value; a function receives the header, query parameter or body key name (the `curl.sh` attachment uses it for `${NAME}` placeholders). Do not combine a function with `colors`. |
| `skipHeaders` | `readonly string[]` | none | Header names (case-insensitive) left out of the command. |
| `truncationMarker` | `string` | none | Appended to a body cut by `maxBodyLength`. |
| `truncationNote` | `(limit, total) => string` | built-in note | Text of the `#` note that announces a cut body. |

## Environment variables {#environment-variables}

These decide the default for `colors` (both loggers) when you do not set it, in this order:

| Variable | Effect |
| --- | --- |
| `NO_COLOR` | Non-empty: colours off. |
| `FORCE_COLOR`, `DEBUG_COLORS` | `0` or `false`: colours off. Any other value (including empty for `FORCE_COLOR`): on. `playwright test` sets both for its workers, which is why colours normally work in test output although the workers' stdout is a pipe. |
| `PLAYWRIGHT_FORCE_TTY` | Anything but `0`/`false`: on. |
| `TERM=dumb` | Off (checked before the TTY test). |
| TTY | On when stdout or stderr is a TTY; otherwise off. |

`colors: true` or `false` in the options always wins, including over `NO_COLOR`.

The curl command has [its own, stricter rule](./api-logging.mdx#curl-colours-gate) and reads a few more variables:

| Variable | Effect |
| --- | --- |
| `CI` and the CI service variables | The curl stays plain. |
| `PLP_RUNNER_TTY` | Set by the library in the test runner process when the runner's own stdout is a terminal (`<runner pid>:<colour depth>`); workers inherit it and, when it names their parent, colour the curl by default. Do not set it yourself: it is ignored unless it holds the runner's pid. See [Local runs in a terminal](./api-logging.mdx#curl-colours-local). |
| `COLORTERM` (`truecolor`, `24bit`), `TERM` (contains `256color`) | The curl uses the 256-colour palette; otherwise the 16 basic colours. |

| Variable | Effect |
| --- | --- |
| `DEBUG=plp` (any value containing `plp`) | Prints a warning when the library could not hide its own frames from Playwright (step locations may then point into the library). |
