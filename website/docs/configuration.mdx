# Configuration

Two option fixtures configure the loggers. Both are optional and flat objects.

```ts title="playwright.config.ts"
import { defineConfig } from '@playwright/test';
import type { LoggerOptions } from 'playwright-logger-pro/fixtures';

export default defineConfig<LoggerOptions>({
  use: {
    apiLog: { curl: 'on-failure' },
    browserLog: { network: 'failed', redact: { values: [process.env.E2E_PASSWORD].filter((v): v is string => !!v) } },
  },
});
```

:::info Documentation is checked against the code
The option tables on this page are compared with the library's option types and exported defaults when the site is built (`npm run check-config` in `website/`). A missing or extra option, or a wrong default, fails the build.
:::

## Precedence and merge rules {#precedence}

- **`test.use()` replaces the whole object.** `test.use({ apiLog: { curl: true } })` replaces the `apiLog` from your config; it does not merge. Repeat the options you still want. The same holds for `browserLog`.
- **`redact` is merged one level deep** with the defaults: setting `redact: { values: [...] }` keeps the default `selectors`, `keys` and the rest. Setting `redact.selectors` or `redact.keys` **replaces** that list.
- **`undefined` means the default.** An option explicitly set to `undefined` uses its default, which lets you write `colors: process.env.CI ? true : undefined`.
- **Explicit `colors` wins** over every colour environment variable.
- **Invalid values never throw.** An unknown option or invalid value prints a one-time `[playwright-logger-pro]` warning naming the option, and the default is used. (`maxEvents` must be a positive integer so a bad value can never switch the failure block off.)
- **apiLog redaction lists are merged** with the built-in lists; see [`replaceDefaultRedaction`](#apilog-options).

## apiLog options {#apilog-options}

Configures request logging for the `request` fixture and `wrapRequestContext()`.

{/* config-table: apiLog */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | `false` makes the wrapper a transparent pass-through. |
| `colors` | `boolean` | auto | `true`/`false` force ANSI colours on/off (`true` wins over `NO_COLOR`). Auto: see [Environment variables](#environment-variables). |
| `curl` | `boolean \| 'on-failure'` | `false` | Print the equivalent curl: never / for every request / only when the status is not 2xx or no response arrived. Other values warn and use `false`. |
| `logHeaders` | `boolean` | `true` | Log request and response headers. |
| `logBody` | `boolean` | `true` | Log request and response bodies. |
| `maxBodyLength` | `number` | `2000` | Truncate logged bodies beyond this many characters. A number ≥ 0; `Infinity` disables truncation. Also applies to the curl body. |
| `redactHeaders` | `string[]` | `[]` plus the built-in `authorization`, `cookie`, `set-cookie`, `x-api-key` | **Extra** header names masked in logs and curl. Case-insensitive; merged with the defaults. |
| `redactQueryParams` | `string[]` | `[]` plus the built-in `api_key`, `apikey`, `token`, `access_token`, `password`, `secret` | **Extra** query parameter names masked in logged URLs and curl. Merged with the defaults. |
| `redactBodyKeys` | `string[]` | `[]` (no built-in keys) | **Extra** JSON/form body keys and multipart field names masked in logged bodies and curl, at any depth. |
| `replaceDefaultRedaction` | `boolean` | `false` | `true` drops the built-in lists: only your lists are used, and a list you leave out redacts nothing. Dangerous. |
| `sink` | `(line: string) => void` | `console.log` | Where log lines go. A throwing sink warns once and falls back to `console.log`. |
| `baseURL` | `string` | fixture: `use.baseURL` | Used to show absolute URLs and the original URL of redirected requests. The fixture fills it in; pass it yourself with `wrapRequestContext()`. |
| `extraHTTPHeaders` | `Record<string, string>` | fixture: `use.extraHTTPHeaders` | Headers the context sends with every request, shown in logged headers and curl. The fixture fills it in; with `wrapRequestContext()` pass the headers you gave `newContext()`. |

## browserLog options {#browserlog-options}

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | `false`: no patches, listeners or session for the test. |
| `colors` | `boolean` | auto | Colours for `print` only. Files and attachments are always plain text. |
| `actions` | `boolean` | `true` | Interactions and navigations (`click`, `fill`, `goto`, ...). |
| `waits` | `boolean` | `true` | `waitFor*`, `locator.waitFor`, `waitForTimeout`. |
| `queries` | `boolean` | `false` | Read-only async calls (`textContent`, `isVisible`, `count`, ...). Results are never logged. |

| `navigation` | `boolean` | `true` | Main-frame navigations, page open/close/popup/crash, dialogs, downloads. |

| `pageErrors` | `boolean` | `true` | Uncaught page exceptions. |
| `network` | `false \| 'failed' \| 'documents' \| 'all'` | `false` | Network capture. `'failed'` = request failures and status ≥ 400; `'documents'` = document, xhr and fetch. Subscribing adds protocol traffic. |
| `networkFilter` | `(r: { url: string; method: string; resourceType: string }) => boolean` | none | Extra filter applied after `network`. |
| `steps` | `boolean \| 'auto'` | `'auto'` | `test.step` integration. `'auto'` is on for Playwright ≥ 1.48. `false` turns it off. |
| `includeApiLog` | `boolean` | `true` | Copy apiLog lines into the attachment and file (never printed twice). |
| `logStart` | `boolean` | `false` | Also print a line when an action starts (needs `print: true`). |
| `slowActionMs` | `number` | `1000` | Highlight actions slower than this many ms; JSONL gets `slow: true`. A number ≥ 0. |
| `location` | `boolean` | `false` | Append the call site in your spec, such as `(login.spec.ts:14)`. Costs one stack capture per action. |
| `maxArgLength` | `number` | `200` | Truncate each rendered argument and console message. A positive integer or `Infinity`. |
| `maxEvents` | `number` | `5000` | Ring buffer per test; the oldest events are dropped and a marker says how many. A positive integer. |
| `redact` | `BrowserRedactConfig` | see below | Secret masking. |
| `print` | `boolean \| 'on-failure'` | `'on-failure'` | Print to `sink`: live (`true`) or one block when the test failed. |
| `attach` | `boolean \| 'on-failure'` | `'on-failure'` | Attach `browser-log` to the report. |
| `attachFormat` | `'text' \| 'jsonl'` | `'text'` | Format of the attachment. |
| `file` | `boolean \| 'on-failure'` | `false` | Write a per-test file. |
| `fileFormat` | `'text' \| 'jsonl'` | `'text'` | Format of the file. |
| `fileDir` | `string` | the test's output directory | Directory for per-test files. Never cleaned by the logger. |
| `sink` | `(line: string) => void` | `console.log` | Where printed text goes. |

### browserLog.redact {#browserlogredact}

{/* config-table: browserLog.redact */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `mask` | `string` | `'***'` | Replacement for masked values. |
| `fillValues` | `'auto' \| 'always' \| 'never'` | `'auto'` | Masking of typed values. `'auto'`: when the target looks sensitive. `'always'`: every typed value. `'never'`: none (`values` still applies). |
| `selectors` | `(string \| RegExp)[]` | `DEFAULT_SENSITIVE_SELECTORS` | Matched against the target's description; strings are case-insensitive substrings. **Replaces** the default list; spread the default to extend it. |
| `values` | `string[]` | `[]` | Literal secrets masked everywhere, in addition to the ones collected automatically. Values shorter than 4 characters are ignored. |
| `keys` | `(string \| RegExp)[]` | the sensitive key patterns | Object keys masked inside arguments. **Replaces** the default patterns. |
| `headers` | `string[]` | apiLog's resolved list: `authorization`, `cookie`, `set-cookie`, `x-api-key` plus your `apiLog.redactHeaders` | Extra header names, added to apiLog's `redactHeaders` (defaults included). |
| `inspectInputType` | `boolean` | `false` | Opt-in DOM probe for `type=password` after a fill. One extra round trip per distinct field. |

## `buildCurl` options {#curl-options}

`buildCurl(info, redactHeaderNames?, options?)` is exported for building a curl yourself: `info` is a `RequestInfo`, the second argument lists header names to mask, and the third is `CurlOptions`:

{/* config-table: curl-options */}
| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `redactQueryParams` | `readonly string[]` | none | Query parameter names whose values are masked in the URL. |
| `redactBodyKeys` | `readonly string[]` | none | JSON/form body keys and multipart field names whose values are masked. |
| `maxBodyLength` | `number` | none | Truncate the request body (and each form/field value) beyond this many characters. |

## Environment variables {#environment-variables}

These decide the default for `colors` (both loggers) when you do not set it, in this order:

| Variable | Effect |
| --- | --- |
| `NO_COLOR` | Non-empty: colours off. |
| `FORCE_COLOR`, `DEBUG_COLORS` | `0` or `false`: colours off. Any other value (including empty for `FORCE_COLOR`): on. `playwright test` sets both for its workers, which is why colours normally work in test output although the workers' stdout is a pipe. |
| `PLAYWRIGHT_FORCE_TTY` | Anything but `0`/`false`: on. |
| `TERM=dumb` | Off (checked before the TTY test). |
| TTY | On when stdout or stderr is a TTY; otherwise off. |

`colors: true` or `false` in the options always wins, including over `NO_COLOR`.

| Variable | Effect |
| --- | --- |
| `DEBUG=plp` (any value containing `plp`) | Prints a warning when the library could not hide its own frames from Playwright (step locations may then point into the library). |
